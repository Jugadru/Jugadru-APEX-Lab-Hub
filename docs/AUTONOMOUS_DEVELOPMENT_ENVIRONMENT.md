# Autonomous Development Environment 3.0 — bounded local development cycle

This is supervised operational automation, not an independent AI engineer. One verified passing Collaboration containing a Hub revision task and Software/Quality roles, exact reviewed checkout, one operator-supplied edit manifest. Recheck actual department and Gateway evidence and import/audit historical engineering memory. Collaboration authorizes neither code nor execution. Prepare existing Development audit/plan and Builder proposal; freeze exact content, prior blobs, source receipts and child plan in cycle digest. Explicit separate approval of the digest and trusted local test execution. One run builds an isolated Git commit via existing Builder, executes fixed unittest suite and hands passing candidate to existing Development AWAITING_CI. Failed tests stop; no automatic repair. Local evidence verification rechecks collaboration, memory, builder log, exact clean candidate and original handoff. Once Development advances, inspect its history instead of interpreting original handoff verification as live status.

Limits: one cycle per collaboration, 16 active, one build attempt, existing 8-file/128KiB/120s test limits and allowlist. Only Hub additive feature/docs paths, no game/Asset Factory writes. No model generation, automatic repair, remote publication, paid calls, self-hosted runner, daemon or merge. Existing manual Development CI receipt/diagnosis/repair (max two separately reviewed repairs) and final operator review remain independent. Trusted local Python is not a sandbox. Keep registries private. Child calls are separate durable checkpoints, not one database transaction; interruption may leave prepared/approved child cases. Recover marks INTERRUPTED, never replays; inspect child records and processes, then create a new reviewed collaboration if needed. Cancel before run cancels child Builder; no remote actions. No claim of game, scientific, GPU or production asset validation.

CLI:
- python3 -m hub.development_cycle --registry PATH prepare MANIFEST --checkout HUB
- show ID to review exact frozen contents and digest.
- approve ID --plan-sha256 HASH
- run ID --plan-sha256 HASH --checkout HUB --trusted-candidate
- verify ID, history ID, recover ID, cancel ID.
Manifest fields schema=1, collaboration_id, objective, edits (existing Builder path/expected_blob/content entries). Same private registry as completed collaboration. Candidate lives under code-BUILDER_ID/checkout. Explicitly review before any publication; existing Development command ci --run-id requires actual exact branch receipt. Mission Control includes cycle state, not raw code. Public smoke uses synthetic additive function and actual tests, no remote write. Existing research/graphics/benchmark systems remain separate with their own approvals. Rollback revert Hub code; preserve additive registry. 2.9 REV1 candidate CI PASS, main gate required before 3.0 merge.
